# Factory Finance — 需求说明

> 状态：Phase 0.1。能力清单按「Phase 0.1 已支持 / 未来阶段」划分，未来功能一律标注计划阶段，
> 未实现功能不得在产品中制造可用假象。

## 1. 产品目标

Factory Finance 是面向**小型注塑加工工厂**的轻量级财务管理系统，最终替代现有 Excel 账目管理方式。系统最终支持：

- 资金账户及资金流水
- 股东出资、借款、垫资及分红
- 客户与供应商管理
- 加工费对账
- 应收账款及回款核销
- 应付账款及付款核销
- 采购、工资、水电费和其他费用
- 固定资产与折旧
- 自动复式记账
- 资产负债表、利润表、现金流量表
- 工厂经营分析
- 后续 AI 财务助手

## 2. 核心产品原则

> **用户负责录入真实业务，系统负责执行财务规则、生成凭证、计算余额及统计报表。**

推论（强制）：

1. 系统不允许用户绕过业务单据直接"改数"制造财务结果；财务结果必须可追溯到业务单据。
2. 系统承担规则执行（借贷平衡、核销规则、余额计算、报表汇总），用户承担事实录入。
3. 业务口径与财务口径分离（详见 `ACCOUNTING_RULES.md`）：营业收入 ≠ 实际收款、经营费用 ≠ 实际付款等。

## 4. Phase 0.1 范围

1. 项目工程骨架（Monorepo、构建、lockfile）。
2. 后端模块化单体基础架构（模块边界 + 公共基础设施 + 可运行工程）。
3. 前端工程初始化（Design Tokens、公共组件、基础布局）。
4. Docker Compose 本地开发环境。
5. 项目架构及约束文档（`docs/` 全套）。
6. Stripe Dashboard Inspired Design System V1.0。
7. 公共 UI 组件基础设施（UI/Shared/Finance 三层）。
8. 基础页面布局（Application Shell + 占位页面）。
9. 自动化测试及截图测试基础设施。

本阶段**不开发真实财务业务，不接入用户的真实 Excel 数据**。

## 5. Phase 0.1 非目标（禁止清单，任务文档第 17 节）

以下内容**明确禁止在本阶段开发**：

- 真实加工费对账业务
- 真实回款及核销业务
- 工资计算
- 费用记账
- 股东出资业务
- 自动会计凭证引擎
- 固定资产折旧
- 财务报表计算
- Excel 历史数据导入
- AI 财务助手
- OCR
- 多租户
- 复杂工作流审批
- 完整生产环境认证体系

同时：

- **不得因为开发顺利而主动进入 Phase 0.2**。
- 不得使用伪造 JWT 或默认放行业务接口的方式模拟正式认证。
- 未开发功能在导航中必须明确标记为尚未实现，不允许出现无响应的假按钮。

## 6. 实施范围（第一版）

- 单工厂、单账套、人民币本位币
- 内部经营财务管理
- 权责发生制

税务处理、制造成本归集、期初余额迁移、会计期间结账等细节留待对应阶段**由架构师确认**，本阶段不得擅自实现未经审核的正式财务规则。

## 7. 验收与停止条件

Phase 0.1 验收标准见任务文档第 18 节；阶段状态置为 `READY_FOR_REVIEW` 后**停止开发**，等待架构师与产品负责人审核。测试环境不具备某项能力时记录 `BLOCKED`，不得伪造通过结果。
