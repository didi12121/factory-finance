# Factory Finance — UI 设计规范（强制）

> 本文档为强制规范，与 `DESIGN_SYSTEM.md` 配套使用：Token 与组件见 `DESIGN_SYSTEM.md`，本文档规定风格、禁止事项、交互与验收。

## 1. 强制设计规范

- UI 唯一主要参考：**Stripe Dashboard**（公开可访问的设计参考：https://stripe.com/ 、https://dashboard.stripe.com/ ）。无法访问登录后页面时使用公开参考与本项目 Design System，不得声称已查看其实际界面。
- 设计定位：**Professional Financial Operations Software** —— 专业、克制、现代、高信息密度、适合长期操作的企业级财务管理系统。
- **不要求像素级复刻 Stripe，不得使用 Stripe 品牌 Logo 或冒充 Stripe 官方产品。**
- 专业感主要依靠**排版、对齐、边框、间距及信息层级**形成。
- 页面文案使用**简洁、具体、业务导向的中文**，避免空洞的 AI 式营销措辞。
- 财务数字严格遵守 `DESIGN_SYSTEM.md` 第 4 节金额展示规范。
- 状态表达必须"文字 + 语义色"，不能只通过颜色区分。

## 2. UI 禁止事项（任务文档第 9 节，完整清单）

禁止以下典型 AI Generated UI 风格：

- 装饰性紫蓝渐变
- 玻璃拟态
- 霓虹光效
- 大面积阴影
- 超大圆角
- 所有内容均采用独立卡片
- 营销型标题和欢迎横幅
- 大面积插画作为后台背景
- Emoji 功能图标
- 无意义的图表和动画
- 大量胶囊形按钮
- 为填充空间而生成的数据
- 页面之间不一致的布局
- 通用 AI SaaS Landing Page 风格

补充：

- **品牌主色为紫色，但不允许将整个页面设计为紫色主题背景。**
- 业务页面禁止直接散落十六进制颜色值（统一用 Token）。
- 未开发功能必须明确标记为尚未实现，**不允许出现无响应的假按钮**；搜索、通知等未实现功能不放置假交互入口。
- 展示数据必须是明确标记的虚构测试数据，禁止真实客户姓名与真实账目。

## 3. 交互与布局规范

### 3.1 响应式断点（至少支持）

| 视口 | 适配要求 |
| --- | --- |
| 1920×1080 | 桌面基准：完整侧边栏 + 内容区 |
| 1440×900 | 桌面常规：同基准，内容自适应 |
| 1280×800 | 桌面最小：侧边栏可折叠，表格容器内滚动 |
| 390×844 | 移动端：**侧边栏转换为抽屉（Sheet/Drawer）**，Header 简化 |

### 3.2 布局规则

- **桌面端优先**。
- 侧边栏支持折叠（224px ↔ 56px），当前路由高亮，使用克制的选中背景（`brand-subtle` 级别），导航分组清晰。
- **移动端侧边栏转换为抽屉**，通过汉堡按钮呼出。
- **宽表格允许在表格容器内横向滚动，但不允许整个页面出现非预期横向滚动**（Playwright 断言页面无横向溢出）。
- 阴影**主要用于浮层、弹窗及必要的层级表达**；普通内容区域优先使用细边框、留白和分割线。
- 内容区统一宽度、内边距（24px）与页面标题位置；区块间距 24px，基准间距单位 4px。
- 表格：行高 44px、表头 40px、表格字号 13px；控件高度 36px、圆角 6px；面板圆角 8px。

### 3.3 组件交互基线

- Dialog / DetailSheet / DropdownMenu / Tooltip 必须支持打开与关闭的完整交互（含 ESC、遮罩点击，遵循组件默认可访问行为）。
- 键盘基本可访问性：Tab 焦点顺序合理、焦点可见、Dialog 打开时焦点进入浮层。
- DataTable 具备列定义、排序、分页、空数据、加载状态，并预留服务端分页能力。
- 禁止为填充空间而生成数据（空状态使用 `EmptyState`，加载使用 `LoadingState`，错误使用 `ErrorState`）。

## 3.5 日期与金额展示（Phase 0.3 补充）

- 业务日期 YYYY-MM-DD、会计月份 YYYY-MM、操作时间 YYYY-MM-DD HH:mm、区间「YYYY-MM-DD 至 YYYY-MM-DD」；
  统一使用 `components/ui/date/` 组件族（手动输入 + 日历 + 清空 + 键盘 + 校验），禁止页面散装日期输入。
- 资金流水金额列使用「流入金额 / 流出金额」（资金事实语义，避免与会计营业收入混淆）。
- 单据编号可点击时使用 link 视觉（brand-foreground + 悬停下划线）。
- 未实现导航使用克制的分组级「规划中」提示，禁止逐项重复状态标签。
- 页面不得向用户暴露 DEMO_TODAY、ISO 分隔符等开发术语。

## 4. 验收标准（UI）

1. 四个断点（1920×1080 / 1440×900 / 1280×800 / 390×844）布局正确，页面无非预期横向溢出。
2. Sidebar 折叠/展开、当前路由高亮、移动端抽屉行为可验证。
3. Dialog、DetailSheet 可打开/关闭；DataTable 排序与分页可验证。
4. 金额展示符合规范（千分位、两位小数、右对齐、tabular-nums）。
5. 正文、按钮、状态文字通过对比度检查（见 `DESIGN_SYSTEM.md` 第 5 节）。
6. 全部页面无第 2 节禁止事项；文案为业务导向中文。
7. Playwright 真实浏览器截图齐备（`artifacts/screenshots/phase-0.1/`），**截图必须来自真实运行的应用**，不得使用生成式图片或静态设计稿冒充；无法查看图片时交由架构师审核，不得声称已完成视觉检查。
8. 视觉回归基线须在**人工审核通过后**再正式固化。
